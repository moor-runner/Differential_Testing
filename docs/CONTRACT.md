# 对拍工作台 v1：协作接口

Windows 10/11, JDK 21. Electron + React + local Monaco. Spring Boot, MyBatis, SQLite. All runtime resources local; optional AI statement organization calls a user-configured OpenAI-compatible service. Data directory: duipai.db, images/, work/, settings.json, ai-settings.json.

## HTTP

Backend binds 127.0.0.1, dynamic port supported via --server.port=0. Environment DUIPAI_TOKEN required (random token generated by Electron); DUIPAI_DATA_DIR optional. Every /api/** request including SSE and images requires HttpOnly cookie duipai_token OR X-Duipai-Token header. No unrestricted CORS. Electron loads bundled frontend from backend static content in production, Vite proxy in dev. Backend stdout emits DUIPAI_READY:<port> after start. GET /api/health returns {status:"ok", javaVersion, dataDir}. POST /api/shutdown requests engine cancellation and graceful application exit, only with valid token.

- GET /api/problems -> ProblemSummary[] {id,title,updatedAt}
- POST /api/editor/java/analyze body `{source:string,offset?:number,operation?:"analyze"|"complete"|"inspect"|"signature"}` -> `{diagnostics,symbols,completions,hover,definition,signatures,activeParameter}`. Default operation is analyze. All source positions are zero-based UTF-16 offsets. Analyze returns diagnostics `{start,end,severity,message,code}` and declared symbols `{name,kind,detail,start,end,selectionStart,selectionEnd}`; complete returns type-aware suggestions `{label,kind,detail,insertText,importName?}`; inspect returns nullable hover `{start,end,contents}` and same-file definition `{start,end}`; signature returns overloads `{label,parameters:string[]}` and activeParameter. Unused fields retain empty arrays/null. Each request uses a separate in-memory javac task against the JDK 21 standard library with annotation processing disabled; it does not generate class files, execute user code or change problems. Source is limited to 200000 UTF-16 code units. Compiler concurrency is bounded; HTTP 429 indicates a busy analyzer. Frontend analysis debounces changes, cancels stale requests and checks model versions before showing results. The three Main.java models remain independent; live diagnostics use Monaco marker owner `java-live` alongside job compiler markers `javac`.
- POST /api/problems body {title} -> Problem
- GET /api/problems/{id} -> Problem
- PUT /api/problems/{id} body full Problem excluding timestamps -> Problem
- DELETE /api/problems/{id} -> 204 (UI asks confirmation)
- POST /api/images multipart field file -> {url:"/api/images/<uuid>.<ext>"}; GET that url -> binary
- GET /api/images/recognition/status -> {available,languages:[{tag,name}],message}, Windows local OCR capability and installed recognizer languages.
- POST /api/images/{filename}/recognize optional JSON {language,region?:{x,y,width,height}} -> {width,height,language,lines:[{text,x,y,width,height,words:[{text,x,y,width,height}]}]}. Region values are integers bounded by the stored image dimensions; invalid regions return 400. A region request recognizes an enhanced problem column and restores every coordinate to the original image pixels; response width/height always refer to the full image. Empty language chooses an installed Chinese recognizer first. The endpoint recognizes only validated stored images and never sends them to an external service. Frontend maps headings and geometry to editable sections, then selectively replaces corresponding Markdown sections while keeping local images and unrelated notes.
- GET /api/settings/layout -> object or {}; PUT /api/settings/layout body object -> object
- GET /api/settings/ai -> {baseUrl,model,apiKeyConfigured}; never returns a saved key. Default baseUrl is https://api.openai.com/v1, model is initially empty.
- PUT /api/settings/ai body {baseUrl,model,apiKey?:string,clearApiKey?:boolean} -> public AI settings. Blank or omitted apiKey preserves the existing key; clearApiKey:true removes it. Both clearing and supplying a new nonempty key is rejected. Saved keys are protected using Windows DPAPI for the current Windows account, in independent ai-settings.json; layout settings are unaffected.
- POST /api/ai/test optional body {requestId?:string} -> {message,model}, sends a small Chat Completions request with saved settings. Saving settings alone never contacts the provider.
- POST /api/ai/organize body {statement:string,requestId?:string} -> {statement:string}. Maximum 100000 characters. Sends model, system/user messages and stream:true to the configured /chat/completions endpoint with Bearer authentication; official api.deepseek.com also receives thinking:{type:"disabled"}. SSE chunks update request progress, and providers returning a full JSON response remain supported. Only the completed validated content is returned. Root addresses gain /v1; custom paths and full completion URLs are accepted. The 120-second request and 2 MiB response bounds apply; redirects are not followed. Empty, truncated, interrupted and invalid responses are rejected. Provider bodies and secrets are not echoed in errors. This endpoint never mutates problems: frontend previews and parses the result, selectively applies sections using normal autosave, and offers undo. Frontend removes local image links and unrelated root sections from sent text, keeps sample line breaks, and retains omitted sections, screenshots and private notes when merging.
- GET /api/ai/requests/{id} -> {id,operation,state,stage,message,elapsedMs,firstResponseMs,receivedCharacters,reasoningCharacters,httpStatus,thinkingDisabled,logs:[{elapsedMs,level,message}]}. requestId is a UUID; omission generates one server-side. State is RUNNING/SUCCEEDED/FAILED/CANCELLED. firstResponseMs is the time to the first non-heartbeat response data. Progress and terminal states are bounded and kept briefly in memory; unknown/expired IDs return 404 and duplicate IDs return 409. No request text, result text, key or reasoning text is exposed in the snapshot or backend logs.
- POST /api/ai/requests/{id}/cancel -> snapshot. Cancels the upstream future/subscription and clears the active slot; a late result cannot alter cancellation or release a subsequent request's slot. Frontend polls progress about once per second with individual timeouts and explicitly cancels on close, user cancellation or its own deadline.
- GET /api/problems/{id}/runs -> JobSnapshot[] newest first (can omit large content from list)
- GET /api/runs/{id} -> complete snapshot including codes snapshot and settings
- POST /api/jobs body {problemId,replaySeed?:string} -> JobSnapshot; 409 if another job active
- GET /api/jobs/{id} -> JobSnapshot
- GET /api/jobs/{id}/events -> SSE event name progress, JSON JobSnapshot, interval 300ms and immediate completion
- POST /api/jobs/{id}/cancel -> JobSnapshot
- GET /api/runs/{id}/export/{input|generator|brute|optimized|generator-stderr|brute-stderr|optimized-stderr} -> UTF-8 text attachment

Problem = {id,title,statement,codes:{generator,brute,optimized},settings:{rounds,startSeed,parallelism,generatorTimeoutMs,bruteTimeoutMs,optimizedTimeoutMs},updatedAt}. Seed is ALWAYS string (signed 64-bit integer), empty/null means random. Defaults: rounds=1000, seed=null, parallelism=4, timeouts=5000/10000/2000. Fresh templates use public class Main; generator parses args[0]. Start must save frontend edits before POST jobs.

Layout size arrays retain `sidebar`, `statement`, `workspace`, `editors`, and `outputs`. Display preferences use `uiMode:[0|1]` (0 = split, 1 = tabs) and `codeTab:[0|1|2]` (generator/brute/optimized). Missing or invalid display values restore split mode and the generator tab. Layout PUT operations are serialized; the desktop close handshake waits for the final layout to be saved.

JobSnapshot = {id,problemId,state,verdict,message,startedAt,completed,total,elapsedMs,roundsPerSecond,maxOptimizedMs,seed,round,input,generator,brute,optimized,firstDifference,compileErrors,codes,settings}. state: COMPILING/RUNNING/FINISHED. verdict: null/PASS/WA/RE/TLE/OLE/BRUTE_ERROR/GENERATOR_ERROR/CE/CANCELLED/INTERNAL_ERROR. round is 1-based display index. completed = number fully judged. ProcessResult = {stdout,stderr,elapsedMs,exitCode,timedOut,outputLimited}; missing program results may be null. firstDifference={line,expected,actual} (1 based) or null. compileErrors=[{role,output,diagnostics:[{line,column,message}]}]. Each content block >1MiB frontend previews 1MiB and links export endpoint. SSE/persist snapshot bounded by engine output cap (8MiB stdout per program, 1MiB stderr). No unbounded stdout accumulation. CE code remains in correct editor.

## Engine internal contract

com.duipai.engine.RunEngine public class, constructed RunEngine(Path workRoot), implements AutoCloseable. Public synchronized Map<String,Object> start(String jobId, Map<String,String> codes, Map<String,Object> settings, String replaySeed, Consumer<Map<String,Object>> onUpdate). Returns immediate COMPILING snapshot. The consumer gets complete snapshots (state FINISHED on completion); snapshots should have id, metrics, results, codes and settings. public Map<String,Object> snapshot(String jobId); public void cancel(String jobId); public boolean isBusy(); public void close(). Backend enriches problemId, persists initial and final snapshot + immutable source/settings, listens for snapshots. Engine owns job scheduling, fresh subprocess per program per round, seed arithmetic (reject 64-bit overflow), javac in backend process via ToolProvider compiler with UTF-8 encoding, cancellation and descendant termination. Compare normalized output lines stripping trailing whitespace, CRLF and final blank lines ONLY. First detected failing completed round in parallel execution wins; cancel all remaining workers. For replay always include all outputs even PASS. maxOptimizedMs includes failed runtime. Cap JVM heap (128MiB), do not create command shells. Track all child processes for exit cleanup.

## Ownership

- backend agent: backend/pom.xml, backend config, com.duipai except engine/, REST/storage/auth/templates/tests.
- engine agent: backend/src/main/java/com/duipai/engine/, backend/src/test/java/com/duipai/engine/.
- frontend agent: frontend/ ONLY, own package.json with React/Monaco/Vite/markdown/KaTeX dependencies.
- root: electron/, root package.json scripts/, docs/, integration, build and packaging.
